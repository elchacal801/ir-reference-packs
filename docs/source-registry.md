For web packs the snapshot is the edition. Each article is one locked input with its own source identity
(`<pack>/<docset>/<slug>/<snapshot>`). The article lists are generated from the published tables of contents by the
recipes' discovery rules (`packs/<pack>/articles.yaml`; docs/update-workflow.md). `irpacks check-updates <pack>`
compares each article's published version metadata with the lock and reports TOC drift.

The book's supplements are registered as **separate source identities**. They are not merged into the book pack.
They are the nine step-by-step Markdown/PDF guides from the publisher's site (`dynamic-ir/supplement/*`). A future
companion pack (`dynamic-ir-steps`) could index them with their own corpus flag.

## Later candidates (not acquired, not reviewed)

The list below is a planning aid only:
* No file has been downloaded.
* No license has been verified.
* No content has been evaluated.

Each candidate needs the full contribution process (CONTRIBUTING.md): a rights review, an edition and version
policy, and evaluation questions. The **applicability** of vendor and online material must be checked per page,
because a recently retrieved page is not necessarily recently written.

| Candidate | Why it complements the current packs | What to check before acquiring | Likely route |
|---|---|---|---|
| CrowdStrike / vendor IR reports and guides | Adversary behaviour and response practice | Usually all rights reserved, so likely `metadata_only` or local-only; vendor bias | Local-only pack or link registry |
| Other CISA guidance: advisories, the #StopRansomware advisory series, the Cloud Security Technical Reference Architecture | Authoritative public-sector procedures, alongside the two CISA packs | U.S. government work in general, but check embedded third-party content; advisories are frequently revised. www.cisa.gov answers every request from this project's cloud environment with an Akamai "Access Denied" page (web pages and PDFs alike), so files must be supplied by the maintainer | Tagged PDF, `structure: outline` (as the two CISA packs), versioned by revision date |
| VERIS (Vocabulary for Event Recording and Incident Sharing) | Structured incident description schema; useful for mappings | Repository license (GitHub); schema versions | JSON schema as native records, not prose chunks |
| Sigma rules (SigmaHQ) | Detection content referenced by the book's detection chapters | DRL 1.1 license; very large and fast-moving; a better fit as an external tool than as a pack | Native records keyed by rule ID, if at all |
| Further SWGDE documents (video, image, audio, vehicle, IoT, skimmer forensics) | Device- and media-specific procedures left out of `swgde-forensics` | The same redistribution policy; check each cover page | `pdf_collection_layout` |

When a candidate is adopted, record its rights decision in `packs/<id>/rights.yaml`, before any build.
